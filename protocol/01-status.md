# 状态

> EN: The two states a final reply may start with, and what must be true before DONE.

交活时**第一行只写状态**，两种形态，没有第三种：

```
STATUS: DONE
STATUS: BLOCKED
```

不写 `PARTIAL`、`MOSTLY`、`DONE_WITH_NOTES`，也不写「已完成，但……」。**没有「一半 DONE」**：验收项没全达成就是 `BLOCKED`。

## 1. 什么才算 `DONE`

`DONE` = **每条验收项都有一条你跑过的命令，或一个你查过的文件**。三个条件同时成立：

1. 每条验收项都有对应证据，不是「应该没问题」。
2. 证据是这一轮跑出来的，对应**现在盘上这份**产物；产物改了就得重跑。
3. 命令的输出原样贴进答复，不是转述；文件给绝对路径。

一条拿不出证据就不是 `DONE`，哪怕代码看起来完全正确。**边界**：「跑过」指这一轮、这份产物；读成「以前跑过」或「看别人跑过」→ 判定翻转。

`DONE` 只说明「我这边做完了」，**不等于被验收**：验收由另一个会话按 `DONE WHEN` 复核，实现者不验自己。

## 2. `BLOCKED` 写什么

三段，缺一段就是没交：

- **缺什么**：卡在哪个外部条件、哪个没人答的问题、哪个拿不到的输入。
- **卡在哪**：试到哪一步，哪条命令的什么输出让你停下。
- **部分证据在哪**：已经落盘的路径；没有就写「无」。

## 3. 为什么不能用「已完成」「差不多」

这两个词描述的是**你的感觉**，不是**盘上的状态**。差别在谁来承担判断：

| 写法 | 读的人要做什么 | 结果 |
|---|---|---|
| `STATUS: DONE` + 命令输出 | 扫一眼输出 | 能据此排下一步 |
| 「已完成」「差不多」「应该好了」 | 自己再验一遍 | 等于没交；验出来不对还要重派 |

更贵的一层：**压缩和交接会把形容词变成事实。** 下一个会话只看到「已完成」，看不到你当时的犹豫，会把它当 `DONE` 往下走。状态词必须自带证据，否则它在传递中升值。

## 4. 状态落两处

**同时**写进最终答复和看板行：答复给叫你的那个会话看，看板给下一个会话看——只写答复，换个窗口就没了。首行之后别停：`DONE WHEN` 仍要逐条对，盘上产物仍要核；**首行是索引，不是结论**。
