# 恢复
> EN: How to resume after compaction or a restart: one sentence, one gap, disk over board.

压缩、resume、新窗口、宿主重启都**不是新任务，也不给新授权**。用户最新的一句话只改它点名的那一条，其余还在。

## 1. 先写一句话复述

三问，按顺序答：**原话要什么 / 还开着什么 / 下一步是什么**。写完再动手。

- 给父代交卷时（工人模式）：第一行 `STATUS: ...`，复述句放第二行。
- 复述用盘上和板上的东西，不用记忆里的印象；对不上就按第 2 节核。

## 2. 找板，然后核板

顺序：项目根的 `HANDOFF.md` / `NOW.md` → 该项目的**子目录**里同名的文件 → 机器级登记表按最长前缀匹配。只查根一级会误判。

**板是写完那一刻的快照，不是真相源。** 读完先跑板上给的核对命令；没有就 `stat` 一个它点名的路径。

- 对不上 → **以盘上为准**，并在回来里说一句。
- **先 stat，再读内容。** 指针指向不存在或已归档的东西，比指向过期更糟。
- 板的合格线三字段：未完成项清单（每项带核对命令）· 当前焦点 · 已知坏在哪。缺字段先补再信。

## 3. 只补一个缺口

一次只补一个；补完再找下一个。同时开三个缺口 = 三个都没收口。

- 要旧会话：有人点名 id / 路径就直读；只有关键词就先查索引，读摘要不读原文。
- 禁止整份读 transcript；它不是交接材料。

## 4. 恢复协议是注入，不是记忆

压缩后看到的「规则回来了」来自注入；注入到达不等于你读过。没收到注入 ≠ 协议不存在——按本页顺序自查。

压缩注入是「继续」信号，不是收工信号：压缩一次、两次都照常继续原任务。

## 5. 收口时才改板

任务真正收口时，把项目自己的板改成三字段（见第 2 节）；没有项目板就不写机器流水账。

- 辅助文件叫 `detail-<date>.md`；只有板才叫 `HANDOFF-<date>.md`。
- 过期登记不删，标 `SUPERSEDED` 并指向当前那份——读者要能一眼看出哪个是当前。

## 6. 重启 / 工人被杀之后

1. 列未收口：看板上还没 close 的工单。
2. 每单按 `DONE WHEN` 验收**盘上产物**——文件存在不等于任务通过。
3. 可续先续：brief 与验收不变，复用已读上下文。
4. 证明不可恢复（会话坏 / 上下文丢）才派新单；新单**链接旧单**，旧行不删。

## 7. 真要交接时写五件

契约 · 当前状态 · 已定决策加理由 · 走过的死路 · 唯一待解问题。不带 transcript。
