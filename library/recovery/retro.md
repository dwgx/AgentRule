> 伴生工具：本页提到的 `<run_all_gates.py>` 不在本仓库。这里给的是格式与判据，不是可直接跑的命令。

> 一句话：一波活收工后回看这一波，产出一页候选清单——改的是**环境**（规则/检查/工具/指针），不是代码。默认**影子**：只记录，不动手。
> （mattpocock `retro` 的本机改造；住这里而不是 omp skill——它不是要跑的会话，是一页判准。）

## 什么时候跑

- 一波派发全部 close 之后（影子跑）。
- Owner 说「复盘 / 反省 / 这轮哪里卡 / 为什么又绕一圈」时。
- 不跑：T0 单件小改；纯只读研究波无派发。

## 四个抽屉（候选只许从这四个里出）

| 抽屉 | 问什么 | 命中时的最小修法 |
|---|---|---|
| 导航 | 哪个信息找了很久才找到？ | 加/改一行指针（先磨措辞，`library/dispatch/writing-for-agents.md` §1）；死指针先修 |
| 检查 | 哪个错本来能被机器抓住？**先读 `run_all_gates.py` 的套件清单**（该工具不在本仓库，见页首「伴生工具」）——已有却没接线的检查本身就是发现，不是要重造 | 接上线 / 加断言 / 进 `briefcheck`；机械违规不许写成散文规则 |
| 标准 | 哪条规则被绕过、该删、或该收词？ | 改 `library/` 里对应的一页；同一句纠正第三次 = 升级成机器门 |
| 工具经济 | 哪个动作贵得不成比例（重复读、整份读、空转）？ | 收成一条命令 / 脚本 / 预算上限 |

## 四触发闸门（候选进规则书前必过）

候选写进规则书前逐条标：命中四触发哪一条（同错第二遍 / 审计抓到 / 同句纠正重复 / 新同事上下文——`library/README.md`）？
**没命中 → 候选留在本页，不写进规则书**（LLM 生成 context file 实测 −3% 成功率 / +20% 成本）。

## 形状（一页，落 `<reports-dir>/RETRO-OPS-<date>.md`）

1. **做对的**（值得固化）——最多 6 条
2. **做错的**（每条带一手收据：板 close 行 / 日志 / 文件路径；不写「感觉」）
3. **候选清单**（四个抽屉逐条；每条：现象 / 证据 / 最小修法 / 四触发命中? / 删条）
4. **与 `library/floor/incidents.md` 对账**——同一条目第二次出现 = 四触发第 1 条命中 → 升级成机器门，而不是再加一行文字

## 影子期（默认）

- 前 3 波只产候选，**不动任何文件**；第 3 波后由 Owner 或父代裁「哪条进规则书」。
- 「一波 close 后自动写候选页」属于自动门（`library/recovery/work.md` 原则 5）：先影子、拿命中率说话，再放它动手。

## 铁规矩

1. 只读摘要/回执/板，不整份读 jsonl。
2. 候选写「现象+证据+最小修法」，不写「要加强意识」。
3. 与 `library/floor/incidents.md` 对账是硬步骤。
4. 本页只产候选；写规则书走四触发闸门。
