# 干活
> EN: Eight principles for non-trivial work: a runnable completion condition, bounded autonomy, minimal writes, evidence, shadow mode first, rollback points.
<!-- summary: 非琐碎活的八条原则：可跑的完成条件、有限自主、最小写入、证据先行。 -->

> 伴生工具：本页提到的 `<gatecheck, run_all_gates.py, omp_dispatch.py>` 不在本仓库。这里给的是格式与判据，不是可直接跑的命令。

小改动直接做（**父代角色除外**：对项目文件只读，见原则 7）。下面只用于非琐碎的活，是参考。

## 原则

1. **完成条件** — 做成什么样算完，要能跑一条命令或看到一个非空文件。弱：「修好」。强：「测试 T 先红后绿」。
2. **有界自主** — 点位清楚就自己做到完，不要把任务卡交回来，也不要先出方案等批准。**猜错会出大事才停**（毁数据 / 花钱 / 停服务 / 两种读法差很远；典型：动 `<project>`、删远程、改别人 harness 的活配置）。其余自己做掉。详见 `library/floor/hard-floor.md`；Owner 反复强调过这条（`library/floor/incidents.md` 里有原话）
3. **最小写入** — 研究可以充分；写入只满足这一次点名。不加功能、抽象、依赖、MCP；旁边的格式、注释、死代码别顺手动，你这次弄出来的无用导入可以删。能 50 行不要 200 行。
4. **证据** — 交卷带刚跑过的那条命令。没跑过标 `[UNVERIFIED]`；没做成写未完成和卡在哪，不换说法当成功。
5. **自动门先影子** — 会自己动手的判据 / 清理 / 开关：先只记录跑一段，拿「命中率 / 误判率 / 成本」说话，再放它动手；判不准就别放行。
6. **生产与实验分家** — 改在跑的东西（服务、面板、流程）先在边上起一份副本验证；自己写的脚本/服务交付前至少冷启动一次（导入、入口、重启都过）。
7. **派发前先占坑，收工前先交账** — 四参必填（`--id --worker --scope --done`），撞路径直接拒，不绕；收工 `close --verdict ok --verify "<真跑过的>"`。**参数以 `board open --help` 为准**（`board` = `~/.local/bin/board.cmd` → `CACHE/board.py`），本页不抄。父代对项目文件**只读**，要改就派一个工人。这是硬规矩，不是偏好。见 `library/dispatch/dispatch.md §派发五步`。
8. **不可逆 / 系统级改动先留回滚点** — 改注册表、页面文件、服务、共享配置、覆盖已有文件之前：① 记录现值 / 导出备份；② 报告里带一条回滚命令；③ 没有回滚路径的按【停】先问（并入「毁数据」一类）。网络类改动是这条的一个实例（`library/floor/hard-floor.md`）；点名授权（两棵 Owner 自管树等）照旧；push 按 `library/floor/hard-floor.md` 三条检查自检后直接推。

## 做成

- 计划、摘要、口头「已经开了」都不算完。
- 说开了网页、会话或子代理，必须带 id 和发出去了没有；账号不对就停。
- 说审计，就只读；说「做」，就做到证据，不要停在计划。
- **生成完就打开产物搜内容**。写文件、跑导出、建索引之后，用一条独立命令（`grep` / `read_bytes` / 计数）从产物里读出你声称写进去的东西。**模型自报的计数不可信**——同一轮它逐字抄对 3 处内容、却把 16 条 bullet 报成 15 条（`library/floor/incidents.md` §仪器）。索引型资源同理：命中数永远小于真实存在量，「查过了」不等于「读过了」。
- 一轮一件事。做完按 `library/recovery/recovery.md` 把项目自己的板改成**三字段**（未完成项清单含各自核对命令 + 当前焦点 + 已知坏在哪）；没有项目板就不写机器流水账。
- 长活收尾跑一次 `gatecheck`；**全量改动（规则 / hook / 检查器）加跑 `run_all_gates.py` 并把尾行戳贴进交付物**（`gatecheck` / `run_all_gates.py` 不在本仓库，见页首「伴生工具」）；踩了门就在回来里说明，不藏。

## 对外动作（评论 / PR / 社媒）

- 批量动作（单轮 ≥3 次，或碰非本人创建的页 / 账号）先报备再动。
- 同站同人一次一条；评论一律机械翻译风格（干净、无 AI 啰嗦），保留「deepseek辅助」标注。
- 删除重发先报原因——被识别成 AI 批量操作是真实风险（GitHub 封号），宁可慢。

## 结论

- 写进交付物的数字当场重算；「只有 / 全部 / 没有」这类全称，要么配同轮全量检索，要么降级成「未确定」。
- 子代理 / 工人的断言，升级成你的结论前自己看一遍源头；要它给复现，不只给判断。
- 同一疑点推两轮还无解：停，写 `[UNVERIFIED]` 和卡点，不静默丢。
- 等的时候按派发通道分两种，**回执读法不同**：
  - **同进程 `task`（in-session）**：`wait` 阻塞到工人退出，然后读 **agent 返回**（`agent://<id>`）。这条通道**本就不写 `last.md`**——去 `ops/jobs/` 找它必然落空，那是找错地方，不是工人没交（`library/dispatch/dispatch.md §派发五步`）。
  - **跨进程 `omp_dispatch.py`**（该工具不在本仓库，见页首「伴生工具」）：读 job 目录 `ops/jobs/<id>/` 的 `last.md` + `receipt.json`，顺序 `receipt.json` → `final.last_md` → 实际产物（`library/dispatch/dispatch.md §恢复`）。
- 其余等法：编译 / 测试让一条命令自己跑完；Owner 下一句 = 本回合结束。等之前确认真有在跑的东西（`wait` 没有 job 会被 `gatecheck` 标 `useless`）。
- **等待必须有上界，过了就降级报告。** 开等之前先算「最坏情况多久」，写下来；到点没结果就**报当前状态 + `[UNVERIFIED]`**，不要继续等。三种典型越界：① 等一个**已经过去的定时器**（本轮实测有 lane 卡了 1h45m 等 10:27 的 cron）；② 等一个**上游已死的模型**（provider 429/503 不会自己好）；③ 等**一条别人已经做完的事**（并发写同一份源时）。降级报告的价值高于卡住：`[UNVERIFIED]` 的结论能被下一个人接手，卡住的 lane 什么都不是。
- 自证有偏袒：要给关键结论做独立验证时，让另一家（或另一个模型族）跑，别用同一条模型自证。
- 说「在跑 / 生效」要有消费方读到它的证据（进程活着不算）；报数前先问一句"这数会不会是我自己口径的错"。
- **检查必须报分母，且分母为 0 算失败**。永远绿的检查比没有检查更糟——本机实测过 `fz.py verify` 对空目录返回 `checked 0 md files … exit 0`。判据：每条校验的输出里要有 `checked N`，`N==0` 必须退非 0。

## 学

- 普通学习、对方法、提高准确：随意联网，不用先问。库文档直读官方文档/仓库（context7 已根除）；网页先搜摘要。
- 看页面、点击、填写、截图：chrome-devtools 驱动 9333，自己做。细则 `library/tooling/browser.md`。

## 不要

- 把「理解一下项目」当成工作本身
- 为以后可能用到的灵活性铺路
- 装插件、加 always-on 提示词来「变聪明」
- 抢 Owner 的桌面焦点——子代理 / 浏览器 / 截图一律静默（BG 桌面或后台），smoke test 点击截图同样静默（Owner 原话 10-14 06:08）
- 手工起的长驻件（进程 / 临时配置）不登记、不收尾——会和托管单元打架
