# 卡（弱档执行卡）
> EN: Ten execution cards for weak models: turn insight into fields you must fill and commands you must run, and paste the matching card into a brief's `# Change`.
<!-- summary: 弱档派活时把洞察换成必填字段和必跑命令，粘进 brief 的 `# Change`。 -->

> **谁能读**：W 档（`deepseek-*` / `glm-*`）。S 档不需要——这些是「把洞察换成必须填的字段」，
> 强模型自己会做，读了是噪音。依据见 lane-rule 的 `high-iq-methods` 报告第 3 节。
>
> **为什么是卡不是散文**：402 次真实门命中里，`recursive-delete` 21.2%、`powershell-dollar` 39.0%
> 的违规，模型在触发前的 thinking 里**已经点名了那条规则**。写在上下文里 ≠ 被执行。
> 卡要求的是**填表**和**跑命令**，不是「意识到」。

派活时把对应的卡原文粘进 brief 的 `# Change` 段。`<…>` 是槽位。

## 卡 M1 · 断言 → 检查 对照表

```
# 交付前必做：断言表
1. 把交付物里每一句「关于某个文件/图/DB 行/命令输出的断言」抄成一行：
   | 断言原文 | 对象路径 | 查它的命令 | 结果(原样贴) |
2. 逐行跑第 3 列；没有命令可写的断言，不许留在交付物里（改写成 [INFERENCE]）
3. 表行数 = 交付物里的断言句数（±0）
失败分支：某行查不了 → 该句降级为 [UNVERIFIED]，并在表里写明「为什么查不了」
```

## 卡 M2 · 先分母

```
1. 第一条命令就数全量：find/ls/git ls-files/sqlite count → 把数写进交付物第 1 行
2. 分类计数：<集合> | sort | uniq -c | sort -rn
3. 结论里每个数字后面跟 (分子/分母, 命令)
4. 没有分母的数字不许出现在结论段
```

## 卡 M3 · 矛盾处理（五步，不许跳）

```
触发：两个数对不上
1. 并排写下两个数，各自标「来源文件 + 时点 + 分母」
2. 列 ≥3 个「两者同时成立」的机制假设（陈旧缓存 / 不同分母 / 重复计数 / 单位不同 / 时点不同）
3. 每个假设写一条能判真假的查询，逐条跑
4. 找到机制 → 用它重算两个数；找不到 → 两个数都留，标 [UNRESOLVED]，**不许选一个**
5. 机制写进交付物的「数据质量」段（不是写进脚注）
```

## 卡 M4 · 口径与边界行

```
1. 把判据原文抄进交付物，逐词标「可判 / 不可判」
2. 不可判的词：找同目录上一份同类产物当先例，抄它的解释
3. 写「边界行」：按另一种读法会改判的行，逐行列出（行号 + 为什么）
4. 边界行 = 0 也要写「边界行：无，因为…」
```

## 卡 M5 · 一手优先（产物版）

```
1. 断言关于 X（图 / 文件 / DB 行 / 接口返回）→ 打开 X 本身
2. 派生字段（OCR 的 text_seen、缓存列、摘要、上一轮的结论）**只能旁证，不能当判据**
3. 打不开 → 先换读法 ≥2 次（旋转 90/180/270、裁剪、放大、换编码、换工具），都不行才写 cannot_read
4. 交付物写「N 个唯一对象，全部打开过」+ 去重后的数
```

## 卡 M6 · 归类计数

```
1. 把错误按「同一句话模板」分组（相同短语 / 相同前缀 / 相同字段）
2. 每组：计数 + 抽 ≥3 条核对 + 给一个机制名
3. 正文只放「类」，逐条清单进附录
4. 每组配一条修法；修法是「删掉这个词」也要写
```

## 卡 M7 · 交付自复算

```
1. DONE WHEN 写成一条命令（不是形容词）
2. 命令输出原文贴进交付物
3. 交付物里每个总数，由本轮脚本重算，不抄输入
4. 脚本用 stdlib + 只读打开（DB 一律 mode=ro）
```

## 卡 M8 · 先例格式

```
1. 交付前先 read 同目录上一份同格式产物
2. 抄它的段标题顺序与字段名
3. 只改内容，不改结构；结构必须改时，在交付物里写「与先例的差异 + 理由」
```

## 卡 M9 · 读不出之前

```
1. 读不出 → 依次问：方向？分辨率？编码？容器格式？权限？
2. 每个问号跑一次（旋转 / 裁剪 / 放大 / decode / file / ls -l）
3. 全失败才写 cannot_read，并在旁边写「试过：<列表>」
```

## 卡 M10 · 边界声明

```
1. 交付物必须有「这条不证明什么」段，≥3 条
2. 每条 = 一个读者可能误读的推论（不是「我可能出错」这种空话）
3. 另起一行写「没碰的路径」：逐条列绝对路径
```

## 拆不出来的（只能靠档位隔离，别指望卡）

- **N1 哪个歧义重要** —— 判断哪个歧义值得停下来问
- **N2 怀疑生成器本身** —— 怀疑产物是工具编的，而不是数据有问题
- **N3 何时停** —— 推两轮无解时该停
- **N4 跨项目迁移** —— 把 A 项目的方法搬到 B 项目
- **N5 拒绝 brief 的省事路径** —— brief 给了一条捷径但你知道它错

这五条写进卡也没用——弱模型会照着字面执行而错过时机。**只能靠：brief 里点名、或父代在 review 时抓。**

## 成本

M1/M2/M7 是命令级，照抄能跑；M3/M4/M6 是表格级，填得出；M5/M8/M9/M10 是清单级。
全部是**输出形状约束**，不要求模型自己意识到什么。

删条：这些卡被门化（同类违规第二次出现 → 变门）之后，对应的卡可删。
