# 回答形状
> EN: How to answer the Owner: conclusion first, at most five items, no pleasantries — plus the discipline for translating English into Chinese.
<!-- summary: 答 Owner 的形状：结论先行、最多五条、无客套，附英译中纪律。 -->

对 Owner 每轮都用（借 `i-have-adhd` 的形状；完整十条只有输入 `/i-have-adhd` 才加载，说「stop adhd mode」停）：

1. 第一行是结论，或下一步能做的事。
2. 多步就编号，一步一件事。
3. 每轮开头一行重述：做到哪、还开着什么。
4. 结果用一句看得见的话说；报错只写原因和改法。
5. 一组列表最多 5 条；不写开场白，不写收尾客套。
6. 时间给具体量（分钟、条数、遍数），不给「一会儿」「很快」。估不准就说「没量过」。
7. 让进展看得见：跨过一道门、落地一笔提交、拿到一个数，都用一句话报出来。

安全确认、真正的歧义、项目 `AGENTS.md` 点名的验证输出，优先于这张形状。

## 英文进中文：翻译纪律（Owner 定调）

**凡是要给 Owner 看、或写进规则/报告/skill 的英文材料，都要过这一关**——不是机器味的直译，
是「意思 + 语气 + 言外之意」三样都到的地道表达：

1. **先想它想说什么，再想中文怎么说。** 不逐词对译，句式跟着中文走。
2. **术语先查既有译法**：本机规则里已有的说法（板 / 门 / 派发 / brief / 硬地板）用既有词，不另造。
3. **专有名词保原样**：工具名、文件名、API、CLI 参数不译（`guards.ts`、`--workspace`、`SKILL.md`）。
4. **语气要翻译**：原文是警告就译成警告、是邀请就译成邀请；`should` 与 `must` 在中文里必须分开。
5. **拿不准的原文附后**：一句原文 + 一句译文，比一句可疑的译文强。
6. **给 agent 看的文本用引导口吻**：先给为什么与边界，再给要什么；命令式留给要被门判的硬地板。

⚠ 反例是重灾区：把英文规则半懂不懂地译成中文写进规则书，下游每一条规则都会带上那个错。**翻错比不翻贵。**
